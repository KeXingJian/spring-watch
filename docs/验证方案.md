# spring-watch-agent 验证方案

> **本文定位**:v2 Agent 上线前必须跑过的四层验证 + 烟测脚本 + 失败诊断清单。
> 四个层级由下到上,前一层不通过则后一层无需跑。

---

## 0. 验证矩阵总览

| 层级 | 目的 | 工具 | 耗时 | 失败后的下一动作 |
|---|---|---|---|---|
| L1 静态 | 代码即文档,眼看即查 | IDE/grep | 10 min | 修代码 |
| L2 单元 | 关键数据结构正确性 | JUnit 5 | 5 min | 修真 bug |
| L3 集成 | mock-test 挂载全链路 | mock-test + -javaagent | 30 min | 修 ByteBuddy / SqlDigest |
| L4 平台回归 | 0 改动承诺 | spring-watch 主仓库联调 | 1 hr | 修契约 |

```
L1 静态 ──→ L2 单元 ──→ L3 集成 ──→ L4 平台回归
   │              │              │              │
   否             否             否             否
   ↓              ↓              ↓              ↓
 修代码         修bug         修织入        修契约
```

## 1. L1 静态审查(15 min)

**目的**:在编译前抓出明显的 import / 类型 / 接缝错误。

### 1.1 必查清单

| 项 | 检查方式 | 通过准则 |
|---|---|---|
| **agent-core 没有同时依赖 sdk 和 agent-instrument-sql** | `mvn dependency:tree -pl agent-core` | agent-core 和 agent-instrument-sql 互不依赖 |
| **SqlDigest 在 agent-core,被两边共用** | `grep -r "SqlDigest" agent-core agent-instrument-sql` | 两边都能引用 |
| **JdbcStorage 在 agent-core 的 `boot` 包,无其他类依赖** | 读 `JdbcStorage.java` 顶部 import | 仅 `java.util` 引用 |
| **Advice 类不引用 agent-core 内部包** | 读 `MethodAdvice.java` / `StatementAdvice.java` 顶部 | 方法 advice 不应 import `com.springwatch.agent.*`(只允许 `com.springwatch.agent.boot.JdbcStorage`) |
| **所有命名空间写对** | `grep -rn "sw_method_\\|sw_sql_\\|sw_log_\\|sw_jvm_" agent-core agent-instrument-sql/src` | 与本节 1.3 命名表一致 |
| **HttpHandler 注解 import** | 读 `LogsHandler.java` `MetricsHandler.java` `CapabilitiesHandler.java` | 都有 `com.sun.net.httpserver.HttpExchange` |
| **AppContext 持有 jdbcExporter** | `grep "jdbcExporter" agent-core/src/main/java/com/springwatch/agent/AppContext.java` | 4 处一致(init / start / route / log) |

### 1.2 关键 import 冲突表

| 类 | 允许引用的包 | 禁止引用 |
|---|---|---|
| `JdbcStorage` | `java.util.*` | agent-core 任何包 |
| `StatementAdvice / PreparedStatementAdvice` | `com.springwatch.agent.boot.JdbcStorage`, `net.bytebuddy.asm.Advice` | `com.springwatch.agent.metric.*` `com.springwatch.agent.sql.JdbcEventExporter` |
| `MethodAdvice` | `com.springwatch.agent.metric.*` `net.bytebuddy.asm.Advice` | `com.springwatch.agent.boot.*` |
| `SqlAdvice` (P1) | `com.springwatch.agent.metric.*` `com.springwatch.agent.sql.SqlDigest` `net.bytebuddy.asm.Advice` | `com.springwatch.agent.boot.*` |
| `MethodInstrumentation / JdbcTemplateInstrumentation` | `com.springwatch.agent.sql.*` `com.springwatch.agent.metric.*` | `com.springwatch.agent.boot.*` |
| `StatementInstrumentation / PreparedStatementInstrumentation` | `com.springwatch.agent.config.*` `com.springwatch.agent.instrument.*` `net.bytebuddy.*` | `com.springwatch.agent.metric.*` `com.springwatch.agent.sql.JdbcEventExporter` |
| `JdbcEventExporter` | `com.springwatch.agent.metric.*` `com.springwatch.agent.sql.SqlDigest` | `com.springwatch.agent.boot.JdbcStorage`(通过 `Class.forName(name, true, null)` 引用) |

### 1.3 命名空间一致性

| 指标名 | 写在哪 | 出现位置 |
|---|---|---|
| `sw_method_calls_total` | MethodAdvice | counter |
| `sw_method_errors_total` | MethodAdvice | counter |
| `sw_method_duration_seconds` | MethodAdvice | histogram(_count / _sum) |
| `sw_method_evicted_total` | (未实现,MetricRegistry 无 entry) | counter |
| `sw_sql_calls_total` | SqlAdvice(P1) + JdbcEventExporter(P2) | counter |
| `sw_sql_errors_total` | SqlAdvice + JdbcEventExporter | counter |
| `sw_sql_duration_seconds` | SqlAdvice + JdbcEventExporter | histogram |
| `sw_sql_slow_total` | SqlAdvice + JdbcEventExporter | counter |
| `sw_sql_digest_evicted_total` | (未实现) | counter |
| `sw_log_dropped_total` | AppContext.onLogDropped | counter |
| `sw_jvm_heap_bytes` | JvmMetricsProvider | gauge |
| `sw_jvm_thread_count` | JvmMetricsProvider | gauge |
| `sw_jvm_gc_count` | JvmMetricsProvider | gauge |
| `sw_jvm_uptime_seconds` | JvmMetricsProvider | gauge |
| `sw_instrumentation_failures_total` | AgentInstaller | counter |
| `sw_http_rejected_total` | (未实现,AgentHttpServer 内部有计数) | counter |

### 1.4 静态审查命令

```bash
# 命名一致性
grep -rn "sw_" agent-core/src/main agent-instrument-sql/src/main | sort -u

# 禁止的 import 引用
grep -rn "import com.springwatch.agent.sql.JdbcEventExporter" agent-instrument-sql/src/main
# 应该为空 — advice 不允许直接依赖 exporter

grep -rn "import com.springwatch.agent.boot" agent-instrument-sql/src/main
# 应该是只有 StatementAdvice / PreparedStatementAdvice 引用 JdbcStorage

# 启动配置
grep -rn "spring.watch.disable" agent-core/src/main
# 默认空集合,开关真正生效
```

## 3. L3 集成测试(30 min)

**目的**:验证 mock-test 挂载 Agent 后,三能力(metrics / logs / SQL)端到端产出。

### 3.1 准备

```bash
# 1. 编译两个仓库
cd spring-watch-sdk && mvn install -DskipTests && cd ..
cd spring-watch-agent && mvn install -DskipTests && cd ..

# 2. 产 fat jar
cd spring-watch-agent/agent-shade
mvn package
ls -lh target/spring-watch-agent.jar
# 预期 ~4-6 MB
```

> **常见坑**:shade 后 jar 里 `META-INF/services/com.springwatch.agent.instrument.InstrumentDefinition`
> 必须三个实现都合并(查 unzip -l target/spring-watch-agent.jar | grep services/)。

### 3.4 失败诊断

| 现象 | 排查 |
|---|---|
| 启动无 `[kxj: bootstrap classloader 已注入]` | MANIFEST 缺 `Premain-Class` / agent jar 路径错 |
| `/metrics` 404 | 端口未监听 / `spring.watch.metrics.port` 拼错 |
| `/metrics` 无 sw_method_* | 描述符匹配失败 / `@WithSpan` 类未被加载 |
| `/metrics` 无 sw_sql_* (P1) | JdbcTemplate 用了 P1 没覆盖的重载 |
| `/metrics` 无 sw_sql_* (P2) | `appendToBootstrapClassLoaderSearch` 失败 / 驱动实现没继承 `java.sql.Statement` |
| sw_sql_digest 解析错 | `SqlDigest.digest` 边界 bug |
| `sw_log_dropped_total` 永远 0 | 突发不够 / 缓冲满不了 |
| OOM | LogRingBuffer 容量配太大 / counter 基数爆炸 |

## 4. L4 平台回归(1 hr)

**目的**:验证 v2 Agent 不破坏 spring-watch 平台现有链路。

### 4.1 平台侧零改动承诺

平台侧 `AgentMetricsCollector` / `AgentLogCollector` **不应改一行代码**。

### 4.2 跑测试

```bash
# 启动 spring-watch 平台
cd spring-watch
mvn spring-boot:run \
  -Dspring-boot.run.jvmArguments="-Dspring.datasource.url=jdbc:postgresql://localhost:5432/springwatch"

# 平台启动后,使用 mock-test 作为目标应用
# 修改 mock-test 的 endpoint 配置(模拟场景):
# 把 metrics endpoint 指向 spring-watch 的 collector
# 把 logs endpoint 指向 spring-watch 的 collector

# 触发业务流量
curl http://localhost:8080/api/orders/find  # 触发 1 次有 @WithSpan 的查询
sleep 1

# 验证 spring-watch 平台:
# 1. AgentMetricsCollector 成功 scrape sw_* 指标
# 2. AgentLogCollector 拉取日志成功(max timestamp 推进)
# 3. InfluxDB 写入 sw_method_* / sw_sql_*(查看 InfluxDB UI)
# 4. 平台 web 端能查到 sw_method_* / sw_sql_* 的图表
```

### 4.3 验收点

| 维度 | 验证 |
|---|---|
| scrape 不报错 | 平台 spring-watch 应用启动日志无 5xx |
| scrape 指标有 sw_* | InfluxDB 写入 `sw_method_*` / `sw_sql_*` |
| 拉取日志有数据 | `tb_log_event` 表新增 row |
| 游标推进 | `max(timestamp)` 持续增加 |
| 平台告警可触发 | 慢 SQL 告警规则匹配 `sw_sql_slow_total` |
| 平台 0 改动 | `git diff` 主仓库无任何文件改动 |

### 4.4 失败诊断

| 现象 | 排查 |
|---|---|
| 平台 500 错误 | 平台启动端口 / 平台连接问题 |
| sw_* 指标未入 InfluxDB | 平台 `OnlinePrometheusParser` 是否跳过 / InfluxDB client 写失败 |
| 响应 502/504 | 网络 / agent 端 HTTP 拒 / 队列满 |
| 业务正常但日志拉取空 | `since` 格式 / `LogRingBuffer` 拿到的 timestamp 与平台期望不一致 |

## 5. 烟测脚本(快速自检)

```bash
#!/bin/bash
# scripts/verify.sh - 5 秒烟测
set -e

HOST=localhost
PORT=9464

echo "=== 1. 存活 ==="
curl -fsS http://$HOST:$PORT/health && echo "OK" || (echo "FAIL" && exit 1)

echo "=== 2. /metrics spring.watch 指标 ==="
N=$(curl -s http://$HOST:$PORT/metrics | grep -c "^sw_")
[ "$N" -gt 5 ] && echo "OK ($N 行)" || (echo "FAIL ($N 行,期望 >5)" && exit 1)

echo "=== 3. /api/agent/capabilities ==="
curl -fsS http://$HOST:$PORT/api/agent/capabilities | head -c 200 && echo && echo "OK"

echo "=== 4. /api/agent/logs since ISO ==="
N=$(curl -s "http://$HOST:$PORT/api/agent/logs?since=2020-01-01T00:00:00Z" | grep -c '"timestamp"')
echo "接受: $N 条日志"

echo "=== 5. 响应头 check ==="
curl -sI "http://$HOST:$PORT/api/agent/logs?since=2020-01-01T00:00:00Z" | grep -i "X-SW-Log-Cursor\|X-SW-Log-Dropped"

echo "=== ALL PASS ==="
```

预期输出:
```
=== 1. 存活 ===
{"status":"UP","uptimeSeconds":120}OK
=== 2. /metrics spring.watch 指标 ===
OK (16 行)
=== 3. /api/agent/capabilities ===
{"version":"1.0.0","metricNamespace":"sw","logBufferCapacity":65536,...}
=== 4. /api/agent/logs since ISO ===
接受: 245 条日志
=== 5. 响应头 check ===
X-SW-Log-Cursor: 246
X-SW-Log-Dropped: 0
=== ALL PASS ===
```

## 7. 失败时降级路径

| 失败点 | 降级策略 |
|---|---|
| bootstrap 注入失败 | P2 不可用,P1 仍可用,平台只损失"Hibernate/MyBatis 走原生 JDBC"的部分 |
| P1 JdbcTemplate 字节码不兼容 | 降级 P1 仅 method + log;P2 补偿 |
| P2 java.sql 层驱动实现变化 | 对应驱动 vendor 加反射字段名候选 |
| LogRingBuffer 容量不足 | 调大 `-Dspring.watch.log.buffer.size` |
| HTTP 拉取成为瓶颈 | 调 `-Dspring.watch.sql.digest.limit` 减少 digest 数 |
| 指标基数爆炸 | 调 `-Dspring.watch.method.cardinality.limit` |
| 平台 JEXL 规则不识别 | 平台 web 端 alert 规则编辑器新增 `sw_` 前缀过滤 |
